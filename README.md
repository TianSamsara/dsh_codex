# Harness Codex 本地桥接

桥接 **1.1.0** · Harness 面板插件 **0.2.0** · Windows / Node.js 20+。

让 DeepSeek Harness 使用本机 Codex 的 ChatGPT 登录，通过 `127.0.0.1:17654/v1` 提供文本、内嵌图片、流式输出与函数工具调用。插件可发现和记忆桥接、选择模型及思考强度、离线启动和自动重连。

## 本版优化

- **进程复用**：最多 3 个 Codex App Server 进程，每个 HTTP 操作独占一个进程。不同聊天仍使用独立原生 thread。
- **配置缓存**：模型目录缓存 5 分钟，配置缓存 60 秒；每次操作仍验证 ChatGPT 登录。选择缓存之外的模型或思考档位时刷新目录；`GET /v1/models?refresh=1` 可手动刷新。
- **原生工具续接**：向 Harness 返回工具调用后，保留正在等待工具结果的原生 turn。下一次 HTTP 请求通过原 JSON-RPC 请求 ID 回传结果，由 Codex 直接继续，不重复发送整段历史、不重复启动模型会话。
- **隔离与恢复**：用桥接生成的随机工具 ID 识别会话，并严格校验历史前缀、模型、思考档位、指令、工具定义、登录身份和配置。历史编辑、压缩或配置变化后重建上下文；不会仅凭相同的聊天文字合并会话。

没有工具 ID 的纯文字聊天，只有调用方传入稳定的 `conversation_id` 或 `X-DSH-Session-ID` 才会续接；否则仍复用进程，保留每次请求独立建会话的行为。不要给不同聊天设置同一个固定会话 ID。

## 安装

先在本机 Codex 完成 ChatGPT 登录，安装 Node.js，再在仓库目录打开 PowerShell：

```powershell
./Setup-Bridge.ps1 -InstallPlugin
```

安装脚本自动定位 `codex.exe`；也可传 `-CodexPath '完整路径\codex.exe'`。设置保存在 `bridge/settings.json`，首次运行生成 `bridge/state/local-key`，两者均忽略提交。保留仓库所在文件夹，插件以本地链接安装。

在 Harness 侧边栏打开 **Codex 桥接**，点击 **自动发现 → 连接并记住**。如果有多个桥接，选择本仓库的 `bridge` 目录。面板显示桥接版本、模型、思考强度、进程复用和会话续接状态。已有会话的模型仍需在输入框模型菜单中切换。

单独安装面板：`./plugin/install.ps1`。卸载面板：`./plugin/install.ps1 -Uninstall`。不修改 Harness 的安装文件、账户凭据或其他模型服务商。

## 更新已有桥接

```powershell
./Update-Bridge.ps1 -BridgeRoot '已有 codex-harness-bridge 文件夹的完整路径'
```

更新器保留密钥、端口、配置和原启动器，备份原源码，并等待当前 HTTP 请求结束。1.1.0 及之后的桥接支持排空请求；排空最多持续 90 秒，避免更新中断后一直拒绝工作。旧版仅在观察到无活动请求时切换。启动失败会尝试恢复源码和原服务。若当前请求迟迟未结束，更新器退出，请稍后重试。

进程重启会释放内存里的原生会话。Harness 保有的完整聊天历史可用于下一次冷启动，后续步骤再续接。源码更新后，在面板点一次“连接并记住”更新脚本指纹；原密钥继续使用。

## 资源与诊断

- 最多保留 24 个会话；会话闲置 30 分钟后卸载，没有会话的进程闲置 90 秒后回收。忙碌的 HTTP 请求不因空闲清理而结束。
- 超时、取消、进程异常时丢弃对应进程和其会话，下一次从 Harness 历史重建；桥接不自动重试已开始的模型操作，避免重复工具副作用。
- 工具全部交由 Harness 执行；桥接关闭 Codex 自身的 shell、MCP、应用、网页搜索和多代理，保留只读沙箱与 ChatGPT 登录限制。支持 Harness 提供的搜索工具。
- `/health` 需要本地密钥，返回版本、能力与复用计数。非流式回复含 `bridge_timing`：准备/模型耗时及进程、会话是否复用。日志仅记录耗时和状态，不记录聊天、工具参数或密钥。
- 仅接受 `127.0.0.1` 回环请求，拒绝浏览器跨域、文件地址和远程图片；图片使用内嵌 data URL。

2026-10-21 本机真实 HTTP 测试：`gpt-6.1-sol` / `low` 请求一次无副作用的测试工具，再回传 `41`，成功得到 `42`。冷启动首步 **11.38 秒**，原会话续接下一步 **2.26 秒**；第二步准备耗时 **3 毫秒**，确认 `process_reused=true`、`session_reused=true`。两步工作内容不同，这不是同请求的前后对照基准；复杂任务耗时仍取决于模型、思考强度、上下文和工具执行。
